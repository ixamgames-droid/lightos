Status-Notiz: Kindprozesse enden unter Windows per TerminateProcess (tests/_kind_ausstieg.py), Ursache gemessen

**Ursache (gemessen 29.10.2026, Windows 11 ARM, x64-Python 3.14.5 emuliert, PySide6 6.11.1, main 674fa9c6):** Nicht die Schleife und nicht die MIDI-Threads, sondern nicht zugestellte `deleteLater()`. `processEvents()` stellt `DeferredDelete` ohne laufende Event-Schleife nicht zu; danach ruft `os._exit` unter Windows `ExitProcess`, und im DLL-Abbau von Qt/Python kommt es zur Zugriffsverletzung. Faktorreihe im pytest-Kind (je 3 Läufe): nackte Qt-App, MIDI-Manager/-Mapper mit ihren Threads, gezeigte Editoren ohne Abbau, nur `close()` → nie; `deleteLater()` ohne Zustellung → 3/3; `deleteLater()` mit `sendPostedEvents(None, DeferredDelete)` → 0/3. Auch mit 0 Runden und ohne pytest-timeout tritt sie auf. Je Kindprozess vorher: eng35 10/10 und stab36 6/6 mit Zugriffsverletzung in `os._exit(0)` (stab36 baut über das Hauptfenster ab), stab38 und eng37 0/12. Auf ARM wurde sie in allen 31 Läufen abgefangen (Rückgabe 0); auf Windows x64 (Sitzung D, 19.10.) nicht immer, daher dort 5 von 7 Fällen rot.

**Fix:** `tests/_kind_ausstieg.py::harter_ausstieg` leert stdout/stderr und beendet unter Windows per `TerminateProcess` (kein DLL-Abbau, Exit-Code bleibt), sonst `os._exit`. Die vier Arbeiter rufen sie nach der Marke. Die Prüfung im Elternteil (Rückgabe 0 **und** Marke) ist unverändert. `tests/test_qa101_kind_ausstieg.py`: Marke + Ausstieg = 0, anderer Code bleibt, absichtlicher Absturz vor der Marke bleibt rot, der Auslöser endet ohne Zugriffsverletzung (unter Windows mit Gegenprobe `os._exit` → Verletzung), die vier Arbeiter nutzen die Hilfe. Mutation „Hilfe nur os._exit“ wird erkannt.

**Offen:** Bestätigung der zehn grünen Läufe auf Windows x64 (dort war die Rückgabe tatsächlich rot). Nicht angefasst: weitere Kinder mit `os._exit(0)` (stab34, tool16, xplat44, qa88) — dort gibt es keinen Befund.
