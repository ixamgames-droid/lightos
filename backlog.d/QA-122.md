Prioritaet: P2

Titel: tests/test_viz50a_panel_geometrie.py braucht allein ueber zwei Minuten und kippt im vollen Gate unter Last ins Zeitlimit

**Herkunft:** Neuheiten-Audit von Sitzung A am 15.11.2026 (Beobachtung im vollen Gate: dreimal Timeout genau in dieser Datei, wenn nebenher gebaut wird; allein 26 Tests in 110-146 s).

**Befund (gemessen):** Ein Einspielen ohne Stempel ueber die eingebaute Bibliothek (244 LightOS-Profile) setzte rund 44 900 SQL-Anweisungen ab: ~9 700 SELECTs, davon ~7 500 einzelne Lazy-Loads der Kanal-Bereiche (N+1), und ~34 000 INSERTs. Ursache in `bibliothek_format._abgleichen`: das Soll-Profil wurde zur Probe in einem Savepoint angelegt, geflusht und zurueckgerollt; `_vergleichsform` las danach je Kanal ohne Bereiche `ranges` einzeln nach, weil `_add_modes` die leere Sammlung nicht vorbelegte. Dazu baute die Testdatei je Test eine frische Library und liess den ersten `ensure_builtins` (alle Dateien neu einspielen, 6-9 s) in sechs bzw. zwei Tests jedes Mal neu laufen.

**Behebung:** `fixture_db._add_modes` belegt `channels`/`ranges` neuer Objekte leer vor (keine Lazy-Loads mehr). `_abgleichen` baut das Soll ueber denselben Codeweg wie `_anlegen`, aber nur im Speicher (`_soll_profil`, Session-Stellvertreter) - keine Probe-INSERTs mehr. Ergebnis von `einspielen()` an der vollen Bibliothek vorher/nachher byte-gleich (alle Tabellen samt IDs, Rueckgabewert, Bericht und Statusmeldungen; einmal nach `ensure_builtins`, einmal nach Einspielen mit geloeschten Rasterformen = 50 aktualisierte Profile). Anweisungen je Einspielen ohne Stempel: 44 868 -> 2 197 (SELECTs 9 695 -> 1 709, Lazy-Loads 7 498 -> 0, INSERTs 33 934 -> 0). In den Tests: `tests/_fixture_quelle.eingespielte_vorlage` baut eine geseedete bzw. eingespielte Library einmal je Modul, jeder Test bekommt eine Kopie (`frische_library(..., vorlage=...)`). Kein Test abgeschwaecht oder uebersprungen; Mutation (ZQ06121 aus der Nachtrag-Liste entfernt) faellt weiter in drei Nachtrag-Tests auf.

**Zeit der Datei allein** (`pytest -q tests/test_viz50a_panel_geometrie.py`, je 3 Laeufe): ruhiger Rechner (Last ~1,3) vorher 89,1 s / 89,0 s / 89,9 s, nachher 22,2 s / 22,2 s / 22,2 s; unter Last (~5, Agenten bauen nebenher) vorher 139,8 s, nachher 29,5 s / 30,2 s / 30,1 s.

**Nachweis ohne Wanduhr:** `tests/test_qa122_einspielen_abfragen.py` zaehlt die Anweisungen ueber einen SQLAlchemy-Event-Listener - keine Lazy-Loads, hoechstens 12 SELECTs je Profil (vorher ~40), auch beim Aktualisieren; dazu der Gleichheitstest Soll-im-Speicher gegen das gespeicherte Profil fuer jede Bibliotheksdatei. Ohne Fix rot.
