Titel: Kleinteile aus dem Neuheiten-Audit: Bildschirmtastatur Umschalt+ß, LAS-28-Marker nur bei gesicherter Migration, README Linux-Paketliste

**Herkunft:** Neuheiten-Audit von Sitzung A am 15.11.2026 (drei Funde, je von einem zweiten Pruefer bestaetigt).

**Befund 1 (Bildschirmtastatur):** `_beschriften()` in `src/ui/bildschirm_tastatur.py` beschriftete im Gross-Modus jede Buchstabentaste mit `upper()`. In Python ist `'ß'.upper()` aber `'SS'`: nach Umschalt zeigte die ß-Taste „SS“ und tippte zwei Zeichen. **Behebung:** ergibt die Grossschreibung mehr als ein Zeichen, bleibt die Taste `ß`. Test `tests/test_qa121_tastatur_eszett.py` (Finger ueber `QTest.touchEvent`).

**Befund 2 (LAS-28-Marker):** Das Speichern schrieb `attribut_migrationen: ["LAS-28"]` immer. Scheiterte beim Laden einer Alt-Show die SH-LASER3W-Erkennung (Geraete-DB-Fehler) oder trug eine Profilkopie noch die alte Kanalform, lief die Flip-Umsetzung nicht, der Marker sperrte sie danach aber fuer immer (`laser_twist#2/#3` wirkungslos, `#1` auf dem falschen Kopf). **Behebung:** `_sh_laser3w_befund()` meldet, ob die Erkennung gesichert lief; der Loader merkt sich das am State (`_las28_ungesichert`, beim Zuruecksetzen geleert), und das Speichern laesst den Marker nur dann weg. Neue Shows und Shows mit Marker bekommen ihn wie bisher. Test `tests/test_qa121_las28_marker_gesichert.py`.

**Befund 3 (README):** Die Linux-Kurzanleitung in `README.md` liess `libxcb-cursor0` weg; ohne das Paket startet Qt 6 unter X11 nicht („Could not load the Qt platform plugin "xcb"“). INSTALL.md nannte es schon. **Behebung:** Paket und Halbsatz in der README ergaenzt; Test `tests/test_qa121_readme_linux_pakete.py` haelt die README-Paketliste als Teilmenge von INSTALL.md.
