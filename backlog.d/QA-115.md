Status-Notiz: Poll-Takt 5 ms statt 50 ms Schlaf; viz13-Smoke unter Linux 69 s -> 32 s

**Herkunft:** Neuheiten-Audit von Sitzung A am 15.11.2026; Messung von Sitzung B (Windows-ARM, 15.11.2026): 26 Tests, je Test ~5 s Seite laden, der Rest viele `_eval`/`_poll`-Aufrufe mit 50 ms Schlaf je Schleifendurchgang (~100 ms je `_eval`).

**Befund:** `_eval` wartete auf das `runJavaScript`-Ergebnis mit `processEvents()` + `time.sleep(0.05)`; das Ergebnis kommt meist nach wenigen Millisekunden, jeder Aufruf kostete trotzdem mindestens 50 ms. `_poll_until_true`/`_emit_until_true` schliefen zwischen zwei Abfragen noch einmal 50 ms blockierend (ohne Ereignisse), das Seiten-Laden pollte ebenso.

**Behebung:** neue gemeinsame Hilfe `tests/_szene_warten.py` (`warte_bis`, `js_eval`, `pumpen`): gepumpt wird im 5-ms-Takt, `_eval` kehrt zurueck, sobald der Callback da ist; zwischen zwei Poll-Abfragen wird 10 ms gepumpt statt 50 ms geschlafen. Die Zustellung bleibt bewusst `processEvents()` (keine verschachtelte `QEventLoop`, die zusaetzlich `DeferredDelete` zustellen und damit das Abbau-Verhalten von `_qt_lifecycle` aendern wuerde). Zeitgrenzen (40 s Laden, 10 s je Abfrage) und alle Aussagen unveraendert; die gezielten Abstaende zwischen wiederholten Emits und `_pump` (Abbau) bleiben wie sie waren. Benutzt von `tests/test_viz13_scene_modules_smoke.py` und dem gemeinsamen Geruest `tests/_viz72_szene.py` (5 Szenen-Dateien). Die uebrigen ~47 Szenen-Dateien haben je eine eigene Kopie von `_eval`/`_poll`; sie koennen bei Bedarf auf dieselbe Hilfe umgestellt werden.

**Messung (Linux x64, offscreen, Datei einzeln, 3 Laeufe):** `test_viz13_scene_modules_smoke.py` vorher 74,5 / 68,1 / 63,4 s (Mittel 68,7 s), nachher 32,4 / 31,5 / 32,5 s (Mittel 32,1 s), alle 26 Tests gruen in jedem Lauf. `test_viz72_spot_pool_umgebung.py` vorher 22,1 s, nachher 10,5 s. Die anderen `_viz72_szene`-Dateien (viz67, viz72b, viz72c, viz90, xplat53) nachher gruen. Auf Windows-ARM ist bei gleichem Anteil ein Lauf deutlich unter 300 s zu erwarten; Bestaetigung durch Sitzung B am Rig steht aus.
